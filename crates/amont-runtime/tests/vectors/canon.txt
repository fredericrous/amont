# Known answers for SPEC.md, "Canonical tree": raw listings of
# `git -c core.quotePath=true ls-tree -r --full-tree T`, each with the
# canonical text `git hash-object --stdin` is then run on. Every
# implementation of canon(T) reads this one file: attest's Rust tests,
# tests/conformance.sh through the canon block of verify.sh and sign/sign.sh,
# and amont, which vendors a byte-identical copy.
#
# The format is strict, and a reader refuses anything else:
#
#   case <name>     opens a case; outside a case only comments (#) and
#                   blank lines may appear
#   in <record>     one listing line, verbatim after "in ", TAB included;
#                   the listing is these lines, each followed by LF
#   out <line>      one line of the expected canonical text, each followed
#                   by LF
#   none            the listing has no canonical text, so no canon(T)
#   end             closes the case
#
# A case holds its "in" lines (maybe none), then either "out" lines or one
# "none", then "end".

end
